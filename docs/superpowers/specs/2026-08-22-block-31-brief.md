# The Organizations item: the owner's rulings of 2026-08-22

Recorded the day they were given, for the same reason the request above is: a
decision that lives only in a conversation dies at the next `/clear`. Block 31a
shipped items 2 to 7; **moving a Station between Organizations is Block 31b**,
and these are the answers it must be built from.

## What the schema makes hard, measured before asking

- **50 tables carry `organization_id`.** 43 of them also carry `company_id` —
  those are mechanical: change the owner where `company_id` is the Station.
- **Seven are Organization-only** and have no `company_id`: `companies`,
  `members`, `roles`, `organization_memberships`, `invitations`,
  `member_field_confirmations`, `report_runs`. Every hard question below is one
  of these.
- **92 composite foreign keys pin tenancy into the key itself** —
  `(company_id, organization_id) → companies(id, organization_id)` — and **not
  one of them is `DEFERRABLE`, and not one has `ON UPDATE CASCADE`.** So the
  move is impossible in a single transaction today: changing the owner on
  `companies` violates every child, and changing a child first violates its own
  key. The way through is a migration making those constraints
  `DEFERRABLE INITIALLY IMMEDIATE` — a catalogue-only change, no table scan —
  and `SET CONSTRAINTS ALL DEFERRED` inside the move.
- **14 tables carry `member_id`.** That is the size of "swap one listener for
  the other", below.

## The rulings

| Question | Ruling |
| --- | --- |
| A listener whose telephone collides with one already at the destination | **The destination's record survives.** The records arriving with the Station are re-pointed to it, and the record that came from the source is retired once emptied. |
| A listener linked to the moved Station AND to another Station that stays | **Copy.** A new record at the destination, the source keeps its own, and only the moved Station's records point at the copy. Each Organization keeps the history that is its own. |
| E-mail, CPF and passport, also unique per Organization | The same rule as the telephone — same person, same treatment. *(Assumption stated by Claude, not contradicted.)* |
| Roles and their rules | **Lost.** They do not travel; the destination's owner creates them again. |
| Before the move | **The operation prints the current rules first** — the roles, their permissions and who held them — so the owner can recreate them. |
| The Station's audit trail | **Travels with the Station.** |
| Pending invitations naming the Station | Cancelled — they grant a role that will no longer exist. *(Assumption.)* |
| Reports already generated | Stay with the source. *(Assumption.)* |
| A blocked or suspended destination | Refuse the move. *(Assumption.)* |
| A source Organization left with no Stations | Allowed. *(Assumption.)* |

## The cost the first ruling carries, stated plainly

**This system has no listener merge.** The merge screen belongs to the music
catalogue — songs, artists, labels, genres, programmes. "Swap one for the other"
therefore means re-pointing **14 tables** that carry `member_id` and retiring one
record, and that machinery has to be built as part of Block 31b.
