# Block 18 — Programmes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A programme becomes a record with a presenter, a producer, a kind, an age rating, a picture, a weekly schedule and a run of dates — on its own screen under Audiência — and a listener can attach a song request to one.

**Architecture:** Two migrations (the enums alone, then the columns, the schedule table and three doors), a screen mirroring `/music/songs`, the removal of the catalogue's shows tab, and one extra step in the widget's music panel. Writes go through `SECURITY DEFINER` doors because `shows` has no insert or update policy; reads use PostgREST keyset like every other list here.

**Tech Stack:** Next.js 15 App Router (server actions), Supabase Postgres 17, pgTAP, Vitest, Playwright, next-intl, Zod, Tailwind.

## Global Constraints

- **Spec:** `docs/superpowers/specs/2026-08-11-block-18-shows-design.md`. D1–D8 live there.
- **Migrations are `0174` and `0175`.** The repository is at `0173`. Confirm with `ls supabase/migrations | tail -3`.
- **Never retype a shipped function body.** If one must change, `grep -l "function public.<name>" supabase/migrations/*.sql` and take the body from the **last** file, extracted by script. This is how 0168 silently reverted 0163's public-key pin.
- **Message catalogues are `messages/{en,pt,es}.json`, CRLF.** Edit by `JSON.parse` → mutate → `(JSON.stringify(o, null, 2) + '\n').replace(/\n/g, '\r\n')`. A shell heredoc with an apostrophe has corrupted them once.
- **`readSessionFor`, never `readSession`,** in anything the widget serves.
- **`npm run db:test` needs a freshly reset database.** `npm run db:reset` is guarded and local-only.
- **The deploy does not carry migrations.** Apply on merge, not after (three occurrences: 13a, 17b, 17c).

```sql
-- Block 18. The two closed vocabularies a programme is described by.

-- Alone in this file, though not for the reason 0166 and 0170 were: `create
-- type` and a statement using it CAN share a transaction, unlike ALTER TYPE ...

comment on type public.show_age_rating is

```

**Files:**
- Create: `supabase/migrations/0175_shows_schedule.sql`, `supabase/tests/43_shows.test.sql`

**Interfaces:**

**`p_bands` is what the operator typed**, one object per band:

```json
[{ "days": [1,2,3,4,5], "starts": "10:00", "ends": "12:30" }]
```

- [ ] **Step 1: Write the failing pgTAP**

Create `supabase/tests/43_shows.test.sql`, `select plan(12)`. Fixtures follow `42_widget_promotions.test.sql`: one Organization, one Station. Set the Station's timezone to `America/Sao_Paulo`.

The twelve assertions:

1. `save_show` without a kind is refused.
2. …without an age rating is refused.
3. …without a start date is refused.
4. …with an empty `p_bands` is refused.
5. A five-day band writes **five rows sharing one `band`**.
6. **An overnight band (`23:00`–`02:00`, Saturday) writes TWO rows** — Saturday 23:00–24:00 and Sunday 00:00–02:00 — **sharing one `band`**.
7. Every row written satisfies `ends_at > starts_at`.
8. Saving the same show again **replaces** its schedule rather than adding to it.
9. `end_show` sets `ends_on` and **leaves the schedule intact**.
10. `shows_on_air` includes a programme whose band covers the Station's local clock now.
11. …and excludes one whose `ends_on` has passed.
12. …and answers in the STATION's timezone: a Station set to `Pacific/Kiritimati` (UTC+14) and one set to `Pacific/Niue` (UTC−11) disagree about the same instant, and each gets its own answer.

**Assertion 12 is the one that matters most.** A `shows_on_air` written against `now()` in UTC passes every test run in the afternoon and is wrong at 21:00.

- [ ] **Step 2: Run it and watch it fail**

Run: `npx supabase test db supabase/tests/43_shows.test.sql --local`
Expected: FAIL — `function public.save_show(...) does not exist`.
(The flag is a positional path plus `--local`; there is no `--file`.)

- [ ] **Step 3: Write the migration**

The columns and the constraint exactly as §4 of the spec gives them. Then the table:

```sql
create table public.show_schedules (
  id              uuid primary key default gen_random_uuid(),
  show_id         uuid not null references public.shows(id),
  organization_id uuid not null,
  company_id      uuid not null,
  band            smallint not null,
  weekday         smallint not null check (weekday between 1 and 7),
  starts_at       time not null,
  ends_at         time not null,
  created_at      timestamptz not null default now(),
  constraint show_schedules_within_a_day check (ends_at > starts_at)
);

create index show_schedules_show_idx on public.show_schedules (show_id, band, weekday);
create index show_schedules_weekday_idx on public.show_schedules (company_id, weekday);

alter table public.show_schedules enable row level security;

create policy show_schedules_select_music_view on public.show_schedules
  for select using (public.has_permission('music.view', company_id));
```

**No `deleted_at`** — the spec's §4 says why, and the comment must repeat it: a
schedule is replaced wholesale, so a soft-deleted band would have to be excluded
by every reader forever.

`save_show` checks `music.manage`, refuses each missing required field with its
own message, upserts the show, deletes every `show_schedules` row for it and
writes the bands fresh. **The overnight split happens here**, and the comment
must say that doing it on read instead is what loses Madrugada Pulchá.

`shows_on_air` converts through the Station's timezone:

```sql
  select s.id
    from public.shows s
    join public.companies c on c.id = s.company_id
    join public.show_schedules sc on sc.show_id = s.id
   where s.company_id = p_company_id
     and s.deleted_at is null
     and (s.ends_on is null or s.ends_on >= (now() at time zone c.timezone)::date)
     and sc.weekday = extract(isodow from (now() at time zone c.timezone))::smallint
     and (now() at time zone c.timezone)::time between sc.starts_at and sc.ends_at;
```

Run: `npm run db:reset && npm run db:test`
Expected: `43_shows.test.sql` 12 of 12, and every other file still passing.

Then replace `shows_on_air` with one using bare `now()`, re-run, and confirm 12 fails. Restore with `npm run db:reset`. A green suite that survives both mutations proves nothing.

### Task 3: The bands, in TypeScript

**Files:** Create `src/lib/shows/bands.ts`, `tests/unit/show-bands.test.ts`

**Interfaces:**
- Produces:
  - `interface Band { days: number[]; starts: string; ends: string }`
  - `interface ScheduleRow { band: number; weekday: number; starts_at: string; ends_at: string }`
  - `toBands(rows: ScheduleRow[]): Band[]`
  - `isOvernight(band: Band): boolean`

**Why it exists:** the screen shows bands, the database holds rows, and the
conversion has to be tested without a browser or a database. `save_show` does
the rows→database direction; this does database→screen.

- [ ] **Step 1: Write the failing test**

```typescript
import { toBands, isOvernight } from '@/lib/shows/bands';

it('groups rows sharing a band marker into one band, days ascending', () => {
  expect(
    toBands([
      { band: 1, weekday: 3, starts_at: '10:00:00', ends_at: '12:30:00' },
      { band: 1, weekday: 1, starts_at: '10:00:00', ends_at: '12:30:00' },
      { band: 1, weekday: 2, starts_at: '10:00:00', ends_at: '12:30:00' },
    ]),
  ).toEqual([{ days: [1, 2, 3], starts: '10:00', ends: '12:30' }]);
});

/**
 * The overnight case, read back. save_show wrote Saturday 23:00–24:00 and
 * Sunday 00:00–02:00 under one marker; the screen must show what was typed.
 */
it('rejoins an overnight band into the hours the operator entered', () => {
  expect(
    toBands([
      { band: 1, weekday: 6, starts_at: '23:00:00', ends_at: '24:00:00' },
      { band: 1, weekday: 7, starts_at: '00:00:00', ends_at: '02:00:00' },
    ]),
  ).toEqual([{ days: [6], starts: '23:00', ends: '02:00' }]);
});

it('keeps two bands apart even when their hours are identical', () => {
  expect(
    toBands([
      { band: 1, weekday: 1, starts_at: '10:00:00', ends_at: '12:00:00' },
      { band: 2, weekday: 5, starts_at: '10:00:00', ends_at: '12:00:00' },
    ]),
  ).toHaveLength(2);
});

it('knows an overnight band from an ordinary one', () => {
  expect(isOvernight({ days: [6], starts: '23:00', ends: '02:00' })).toBe(true);
  expect(isOvernight({ days: [1], starts: '10:00', ends: '12:30' })).toBe(false);
});
```

- [ ] **Step 2: Run it, watch it fail, implement**

The overnight rejoin: within one marker, a row ending at `24:00:00` and a row
starting at `00:00:00` on the following weekday (wrapping 7→1) are the two
halves of one band. The band's day is the day it **starts** on.
